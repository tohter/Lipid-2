## 2. Почему это дороже прочего

* **Перевёрнутый агент** — самый дорогой класс ошибки в проекте (см.
  EVENTS_TASK.md): событие `мяч бросил` обучает модель тому, что мячи бросают.
* **Отрицание не тому придаточному** даёт запись ровно противоположного смысла.
  Это не потеря знания, а подмена.
* **Узел `который`** попадает в граф, в неизвестные слова и, значит, **Учителю**:
  вопрос «что такое который?» с ответом-определением оседает в онтологии навсегда.
  Замер: `content_lemmas` до правки содержал `который` во всех трёх случаях с
  союзным словом.
* **Форма вместо леммы** (`жила`) расщепляет концепт: `жить` и `жила` — два узла,
  и собрать их обратно уже нельзя (об этом — memory.txt, лемматизация).

## 3. Общая причина — одна, а не четыре

У сложноподчинённого предложения искали **ОДИН субъект и ОДНО сказуемое на весь
текст**. Второе сказуемое остаётся без пары, и главное предложение либо теряет
сказуемое («укатился»), либо получает чужое («дом CAN_DO жить»). Отрицание,
выбранное по всему предложению, достаёт не тому придаточному.

Отсюда же и мусор: вырезанное из синтаксиса союзное слово морфологически
прилагательное (`ADJF`), оно попадает в значимые слова и становится свойством.

## 4. Замер, изменивший правило: падеж «который» нельзя брать у словаря

Первая идея — определить падеж союзного слова по наиболее вероятному разбору
словаря. **Замер убил эту идею:**

```
«который» (в форме придаточного)  -> слов. вероятность: им.п. ВЫШЕ
```

Словарь считает, что `который` чаще в имительном. Но в
«Мяч, который бросил мальчик» он винительный, и разница падежей — это РАЗНИЦА
РОЛЕЙ: имительный = союзное слово есть агент, винительный = пациент. Взять
словарную вероятность — значит стабильно путать кто кого бросает.

Правило стало таким: падеж берётся из **состава самой придаточной части**.

```
есть другое существительное, которое НЕ МОЖЕТ быть винительным
   (мальчик/пёс/река/книга — только им.п.)  -> оно субъект, «который» = вин.п.
иначе                                       -> «который» = им.п., он субъект
```

Это не «кажущееся правдоподобным» решение: оно опирается на замер омонимии
падежей (`кот`/`мяч` = им. или вин., `мальчик` = только им.). Проверка —
`tests/test_subordinate_contract.py::TestRoleAssignment`, четыре направления
(им./вин. × человек/вещь).

## 5. Замер частоты: граница по запятой покрывает реальный вход

Скрипт `/tmp/amanda/p18_freq3.py`, считал **строковые литералы с кириллицей из
`tests/`** — то, что реально подаётся экстрактору (первая версия считала весь
текст доков и врала: 43% «придаточных без запятой» оказались строками вида
`HAS_PROPERTY--> который`).

```
предложений с признаком придаточного: 15
   с запятой перед союзным словом (граница ВИДНА):  14   (93%)
   без запятой       (граница НЕ видна):             1   (7%)
   из них реальных придаточных без запятой:          0
```

Поэтому граница сегмента строится **по запятой у маркера придаточного**, а не
по смыслу. Простое предложение при этом идёт прежним плоским путём без единого
изменения — ровно то, что требует п.6.

Накладные расходы замера (`/tmp/amanda/p18_perf2.py`, минимум из 3 прогонов):

```
простое предложение:   0.113 мс     (split_clauses добавляет 0.015 мс)
с придаточным:         0.199 мс     (два прохода разбора — по частям)
```

## 6. Что сделано

1. **`core/morph.py`**
   * `RELATIVE_GRAMMEMES = {Subx, Anph, Apro}` — союзное слово узнаётся по
     ГРАММЕМАМ, а не по списку слов (замер: у всех форм `котор-*` они есть, у
     `какой`, `чей`, `пушистый` — нет). Тест проверяет не список, а узнавание.
   * Союзное слово больше **не значимое** (`content=False`), но для экстрактора
     остаётся РАЗЛИЧИМЫМ в ключе `relative` — по нему ищется граница.
   * `split_clauses()` — режет предложение по маркерам придаточного вместе с
     окружающими запятыми. Обычные однородные части и приложение НЕ режет
     (замер: «Кошка, пушистая, спала» остаётся одним сегментом).
   * Токен получил `start`/`end` — без позиций нельзя вернуть вырезанный текст,
     потому что граница придаточного это запятая, то есть место МЕЖДУ слов.
2. **`core/extract.py`**
   * `extract()` — диспетчер: нет придаточного → прежний `_extract_flat()` без
     изменений; есть → разбор по частям.
   * **Скелет** главного предложения: части придаточного **вырезаны целиком**, а
     не заменены пустотой (иначе «Дом, где жил пёс, сгорел» несло бы «жила»).
   * `evidence` остаётся **исходным** предложением: скелет — служебная строка,
     которой в тексте нет, а по `evidence` ищут источник связи.
   * `_relative_part()` — падеж союзного слова, антецедент, роли, событие.
   * `_purpose_part()` — придаточное цели на `PURPOSE` (отношение **уже было**
     в реестре `core/storage.py`, придаточное до него просто не доходило).
   * Глагольный хвост в `_fact()` больше не берётся у `_case_role()`: тот ищет
     существительные, а у глагольной формы словарь обязан дать омонима — так в
     граф и легла «жила» вместо «жить».
   * Факты придаточного помечаются `predicate="event"`, как и факты плоского
     пути: произошедшее в придаточном не обязано оседать как вечное знание о
     виде.

## 8. Мутационная проверка (тесты обязаны ловить возврат дефектов)

Мутации применялись заменой **фактических** строк кода; первые попытки «заменить
по памяти» молча не применялись и давали ложно-зелёный результат — проверка
шаблона обязательна.

```
M1  союзное слово снова значимое (relative = False)         -> упало 8 тестов
M2  сложное предложение не дробится (if True)               -> упало 9 тестов
M3  PURPOSE придаточного цели выключен                       -> упало 1 тест
M4  `_relative_part` выключена (антецедент забыт)            -> упало 3 теста
M5  глагольный хвост снова берётся у `_case_role`            -> упало 1 тест
M6  факты придаточного не помечаются событием                -> упало 1 тест
после отката всех мутаций                                   -> OK
```

## 9. Честные ограничения (не замалчивать)

1. **Граница придаточного без запятой не находится.** «Дом где жил пёс сгорел»
   → `дом CAN_DO жить` + заметка «придаточное: связи могут быть разорваны».
   Реальных таких входов в корпусе **0** (п.5). Правится только синтаксическим
   парсером, его в проекте нет — и заводить его ради нуля входов нельзя.
2. **Связь «где» с местом НЕ записана.** Для «Дом, где жил пёс» получается
   `пёс CAN_DO жить` и `дом CAN_DO сгореть`, но **нет** `дом --LOCATED_IN-->
   жить`, хотя отношение `LOCATED_IN` в реестре есть, а предложный путь его
   пишет (`спит на подоконнике` → `подоконник --LOCATED_IN--> спать`). Причина:
   «где» — наречие, оно не даётся граммемами союзного слова, а антецедент живёт
   в СОСЕДНЕЙ части и в общий разбор придаточного не попадает. Следствие —
   общая заметка о разрыве связей, то есть потеря объявлена. **Записано в очередь
   как отдельная задача.**
3. **`есть` выпадает из графа.** «…чтобы не есть её» не даёт ни одной связи,
   потому что `есть` стоит в `STOP`/`STOP_LEMMAS` как **связка**. Замер
   несогласованности: «Кошка **ест** рыбу» → узел `есть` создаётся, а «чтобы не
   **есть**» → не создаётся. Одна лексема видна в одной форме и невидна в
   другой. Чинится в стоп-листе морфологии (влияет на весь корпус), а не здесь;
   зафиксировано тестом `test_stopword_verb_makes_purpose_invisible`, который
   **обязан упасть** при починке — чтобы она была осознанной.
4. **Омонимия «заросли» (глагол/существительное) не разрешается.** Придаточное
   «берега которой заросли» остаётся неразобранным. Требование здесь не
   «разобрать любой ценой», а не сочинять связи — до правки оно давало
   `замёрзнуть --OBJECT_OF--> берег`.
5. Придаточное определительное с **местоимением-подлежащим** («Кот, которого я
   видел, спал») даёт событие без субъекта и заметку «актор — местоимение»:
   это прежнее поведение проекта по отношению к местоимениям, здесь оно не
   менялось.
