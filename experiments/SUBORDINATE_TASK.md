## 2. Почему это дороже прочего

* **Перевёрнутый агент** — самый дорогой класс ошибки в проекте (см.
  EVENTS_TASK.md): событие `мяч бросил` обучает модель тому, что мячи бросают.
* **Отрицание не тому придаточному** даёт запись ровно противоположного смысла.
  Это не потеря знания, а подмена.
* **Узел `который`** попадает в граф, в неизвестные слова и, значит, **Учителю**:
  вопрос «что такое который?» с ответом-определением оседает в онтологии навсегда.
  Замер: `content_lemmas` до правки содержал `который` во всех трёх случаях с
  союзным словом.
* **Форма вместо леммы** (`жила`) расщепляет концепт: `жить` и `жила` — два узла,
  и собрать их обратно уже нельзя (об этом — memory.txt, лемматизация).

## 3. Общая причина — одна, а не четыре

У сложноподчинённого предложения искали **ОДИН субъект и ОДНО сказуемое на весь
текст**. Второе сказуемое остаётся без пары, и главное предложение либо теряет
сказуемое («укатился»), либо получает чужое («дом CAN_DO жить»). Отрицание,
выбранное по всему предложению, достаёт не тому придаточному.

Отсюда же и мусор: вырезанное из синтаксиса союзное слово морфологически
прилагательное (`ADJF`), оно попадает в значимые слова и становится свойством.

## 4. Замер, изменивший правило: падеж «который» нельзя брать у словаря

Первая идея — определить падеж союзного слова по наиболее вероятному разбору
словаря. **Замер убил эту идею:**

```
«который» (в форме придаточного)  -> слов. вероятность: им.п. ВЫШЕ
```

Словарь считает, что `который` чаще в имительном. Но в
«Мяч, который бросил мальчик» он винительный, и разница падежей — это РАЗНИЦА
РОЛЕЙ: имительный = союзное слово есть агент, винительный = пациент. Взять
словарную вероятность — значит стабильно путать кто кого бросает.

Правило стало таким: падеж берётся из **состава самой придаточной части**.

```
есть другое существительное, которое НЕ МОЖЕТ быть винительным
   (мальчик/пёс/река/книга — только им.п.)  -> оно субъект, «который» = вин.п.
иначе                                       -> «который» = им.п., он субъект
```

Это не «кажущееся правдоподобным» решение: оно опирается на замер омонимии
падежей (`кот`/`мяч` = им. или вин., `мальчик` = только им.). Проверка —
`tests/test_subordinate_contract.py::TestRoleAssignment`, четыре направления
(им./вин. × человек/вещь).

## 5. Замер частоты: граница по запятой покрывает реальный вход

Скрипт `/tmp/amanda/p18_freq3.py`, считал **строковые литералы с кириллицей из
`tests/`** — то, что реально подаётся экстрактору (первая версия считала весь
текст доков и врала: 43% «придаточных без запятой» оказались строками вида
`HAS_PROPERTY--> который`).

```
предложений с признаком придаточного: 15
   с запятой перед союзным словом (граница ВИДНА):  14   (93%)
   без запятой       (граница НЕ видна):             1   (7%)
   из них реальных придаточных без запятой:          0
```

Поэтому граница сегмента строится **по запятой у маркера придаточного**, а не
по смыслу. Простое предложение при этом идёт прежним плоским путём без единого
изменения — ровно то, что требует п.6.

Накладные расходы замера (`/tmp/amanda/p18_perf2.py`, минимум из 3 прогонов):

```
простое предложение:   0.113 мс     (split_clauses добавляет 0.015 мс)
с придаточным:         0.199 мс     (два прохода разбора — по частям)
```

## 6. Что сделано

1. **`core/morph.py`**
   * `RELATIVE_GRAMMEMES = {Subx, Anph, Apro}` — союзное слово узнаётся по
     ГРАММЕМАМ, а не по списку слов (замер: у всех форм `котор-*` они есть, у
     `какой`, `чей`, `пушистый` — нет). Тест проверяет не список, а узнавание.
   * Союзное слово больше **не значимое** (`content=False`), но для экстрактора
     остаётся РАЗЛИЧИМЫМ в ключе `relative` — по нему ищется граница.
   * `split_clauses()` — режет предложение по маркерам придаточного вместе с
     окружающими запятыми. Обычные однородные части и приложение НЕ режет
     (замер: «Кошка, пушистая, спала» остаётся одним сегментом).
   * Токен получил `start`/`end` — без позиций нельзя вернуть вырезанный текст,
     потому что граница придаточного это запятая, то есть место МЕЖДУ слов.
2. **`core/extract.py`**
   * `extract()` — диспетчер: нет придаточного → прежний `_extract_flat()` без
     изменений; есть → разбор по частям.
   * **Скелет** главного предложения: части придаточного **вырезаны целиком**, а
     не заменены пустотой (иначе «Дом, где жил пёс, сгорел» несло бы «жила»).
   * `evidence` остаётся **исходным** предложением: скелет — служебная строка,
     которой в тексте нет, а по `evidence` ищут источник связи.
   * `_relative_part()` — падеж союзного слова, антецедент, роли, событие.
   * `_purpose_part()` — придаточное цели на `PURPOSE` (отношение **уже было**
     в реестре `core/storage.py`, придаточное до него просто не доходило).
   * Глагольный хвост в `_fact()` больше не берётся у `_case_role()`: тот ищет
     существительные, а у глагольной формы словарь обязан дать омонима — так в
     граф и легла «жила» вместо «жить».
   * Факты придаточного помечаются `predicate="event"`, как и факты плоского
     пути: произошедшее в придаточном не обязано оседать как вечное знание о
     виде.

## 8. Мутационная проверка (тесты обязаны ловить возврат дефектов)

Мутации применялись заменой **фактических** строк кода; первые попытки «заменить
по памяти» молча не применялись и давали ложно-зелёный результат — проверка
шаблона обязательна.

```

M2  сложное предложение не дробится (if True)               -> упало 9 тестов
M3  PURPOSE придаточного цели выключен                       -> упало 1 тест
M4  `_relative_part` выключена (антецедент забыт)            -> упало 3 теста

M6  факты придаточного не помечаются событием                -> упало 1 тест
после отката всех мутаций                                   -> OK
```

## 9. Честные ограничения (не замалчивать)

1. **Граница придаточного без запятой не находится.** «Дом где жил пёс сгорел»
   → `дом CAN_DO жить` + заметка «придаточное: связи могут быть разорваны».
   Реальных таких входов в корпусе **0** (п.5). Правится только синтаксическим
   парсером, его в проекте нет — и заводить его ради нуля входов нельзя.
2. **Связь «где» с местом — ЗАКРЫТА (очередь B, f8f46e1).** Было: для
   «Дом, где жил пёс» получались `пёс CAN_DO жить` и `дом CAN_DO сгореть`, но
   НЕ было связи с местом. Стало: `жить --LOCATED_IN--> дом`.

   ДВЕ ОШИБКИ В САМОЙ ПОСТАНОВКЕ (замерено, см. раздел 11):
   а) направление было обратным: `дом --LOCATED_IN--> жить`. ВСЕ пути
      разметки пишут «действие -> место», и оно заперто
      `tests/test_learning_contract.py:99` — `("сидеть","LOCATED_IN",
      "подоконник")`;
   б) причин было ТРИ, а не одна; «где» — только верхушка.

ПОЛНЫЕ ЗАМЕРЫ И МУТАЦИИ — раздел 11 внизу файла.

3. **`есть` выпадает из графа — ЗАКРЫТО (очередь C, d3a286d, раздел 12).**
   Постановка была неточна в двух местах: `есть` сидит в `STOP` (словоформа),
   а не в `STOP_LEMMAS`; и причин две, вторая — порог шума в `_purpose_part`,
   со стоп-листом не связана. Самого дорогого дефекта очередь не называла:
   «Кошка будет есть рыбу.» давало `кошка --IS_ROLE--> рыба`.
   Замер несогласованности подтвердился: «Кошка **ест** рыбу» → узел есть,
   «чтобы не **есть**» → нет. Тест `test_stopword_verb_makes_purpose_invisible`
   при починке УПАЛ (как и был приказан) и заменён позитивным замком.
   ПОЛНЫЕ ЗАМЕРЫ И МУТАЦИИ — раздел 12 внизу файла.
4. **Омонимия «заросли» (глагол/существительное) не разрешается.** Придаточное
   «берега которой заросли» остаётся неразобранным. Требование здесь не
   «разобрать любой ценой», а не сочинять связи — до правки оно давало
   `замёрзнуть --OBJECT_OF--> берег`.
5. Придаточное определительное с **местоимением-подлежащим** («Кот, которого я
   видел, спал») даёт событие без субъекта и заметку «актор — местоимение»:
   это прежнее поведение проекта по отношению к местоимениям, здесь оно не
   менялось.

## 11. Очередь B: место в придаточном (закрыто, f8f46e1)

ЗАМЕР ДО ПРАВКИ (скрипт в теле коммита, `LIPID2_STATUS=0`, LLM выключен):

| предложение | было |
|---|---|
| `Дом, где жил пёс, сгорел.` | `дом CAN_DO сгореть`, `пёс CAN_DO жить` — места нет |
| `Дом, в котором жил пёс, сгорел.` | `дом HAS_PROPERTY который` — ХУЖЕ «где»: сказуемое главного потеряно |
| `Стул, на котором сидит пёс, сломан.` | `стул HAS_PROPERTY который` |
| `Город, где живут псы, большой.` | `город HAS_PROPERTY большой`, `пёс CAN_DO жить` — места нет |
| `Я был там, где жил пёс.` | `_antecedent` -> `''` — антецедента нет |

ТРИ ПРИЧИНЫ:

1. **`котором` не распознавался как союзное слово.** `is_relative_pronoun`
   требовал `all()` по всем вариантам, а pymorphy3 доклеивает к «котором»
   мусор «котор» (NOUN) при `score 0.003` — примерно в 300 раз тише верного
   разбора. Из-за этого «в котором» НЕ шло путём союзного слова и оседало
   СВОЙСТВОМ сущности — тот самый дефект п.18, в новой форме.

   ЗАМЕР ПОРОГА (не на трёх примерах, а по `experiments/ru_words.txt`,
   108 517 форм): по одним лишь граммемам `Subx+Anph+Apro` признак признаёт
   союзными **13** словоформ, и **12** из них — указательные «тот, та, эту,
   тех, этот, эта, эти, этой, этих, этими, этою». «том» и «котором»
   морфемно НЕРАЗЛИЧИМЫ: у обоих `ADJF+Anph+Apro+Subx+loct+masc|neut+sing`,
   различие только в лемме. Поэтому ослабление `all()` запрещено на всю
   словоформу — нужен фильтр ПО ЛЕММЕ (`RELATIVE_LEMMAS = {который}`).
   Итог замера правила: потерь 0, приобретений 0, кроме нужного «котором».

2. **Предлог перетекал через союзное слово.** В «в котором жил пёс» «в»
   оставался висеть ещё на трёх словах, доставал «пёс», тот терял
   подлежащее (`prep='в'`), и придаточное не давало НИ ОДНОГО `CAN_DO`:
   `others` пустой, заметка «нет ни подлежащего, ни сказуемого».
   Починка: союзное слово — голова предлога, на нём предлог сгорает.

3. **Предложный падеж числился принадлежностью.** Ветке `else` («река,
   берега которой заросли») доставался и `loc`, то есть «дом, в котором жил
   пёс» трактовался как «дом кому-то принадлежит». Добавлена отдельная
   loc-ветка (возвращает агента) и `_where_place`.

ПОЧЕМУ `_where_place` ВЫЗЫВАЕТСЯ ИЗ ЦИКЛА ЧАСТЕЙ, А НЕ ВНУТРИ
`_relative_part`: первая же правка вызвала его из `_relative_part` и тесты
не позеленели — вызов был НЕДОСТИЖИМ и для «где» (у наречия нет ключа
`relative`, метод выходит в первых строках), и для «в котором» (loc уходил
в ветку принадлежности и возвращался раньше). ЗАМЕРЕНО на живом выводе,
не по чтению кода.

ЗАЩИТА ОТ ЛОЖНОГО МЕСТА. Предложный падеж — НЕ всегда место: `о/об` дают
`ABOUT` (`PREP_CASES`). Мутация «всякий предложный союз = место» дала
`мечтать --LOCATED_IN--> дом` на «Дом, о котором мечтал пёс, сгорел.» —
пёс мечтал НЕ внутри дома. Отсечено той же `prep_is_place`, что и плоский
путь: две ветки одного предложения не расходятся во мнениях.
ФОРМА ДЛЯ ТЕСТА ВАЖНА: нужен именно «о КОТОРОМ» (`loct`); у «о которой»
pymorphy первым вариантом даёт род.п., и такая проверка защиту НЕ трогает
(замер: тест на «о которой» позеленел под верной мутацией).

БЕЗ АНТЕЦЕДЕНТА СВЯЗЬ НЕ СОЧИНЯЕТСЯ: «Я был там, где жил пёс» —
`_antecedent` возвращает `''`, связь не пишется, заметка громкая.

ЗАМОК: `tests/test_where_location_contract.py`, 14 тестов, красный ДО правки
(6 падений). МУТАЦИИ (каждая ломает замок): убрать вызов `_where_place`
— 4 падения; вернуть старый `all()` — 4; убрать фильтр по лемме — 2;
предлог снова перетекает — 2; убрать loc-ветку — 2; всякий предлог = место
— 1. Последняя мутация сначала НЕ падала: тест стоял на «о которой» — то
есть проверка состоялась только после замера, какая форма её касается.

ЗАМЕРЕНО ПОСЛЕ: 537 -> 551 OK; sha256 живой памяти
`d92760c1f7a737b44179b3e85723cfb6ede483acf13b9d579a8b19c4a4d767c7` не

## 12. Очередь C: глагол «есть» (закрыто, d3a286d)

ЗАМЕР ДО ПРАВОК (LIPID2_STATUS=0, LLM выключен, живая память не тронута):

    «Кошка спрятала мышь, чтобы не есть её.»
        [('кошка','CAN_DO','спрятать'), ('спрятать','OBJECT_OF','мышь')]   цели НЕТ
    эталоны той же конструкции (замерены рядом, та же конструкция):
        «…чтобы не ЛОВИТЬ её.» -> ('спрятать','PURPOSE','ловить')
        «…чтобы СЪЕСТЬ её.»    -> ('спрятать','PURPOSE','съесть')
        «…чтобы не ЖРАТЬ её.»  -> ('спрятать','PURPOSE','жрать')
    Одна лексема невидима в одной форме.

    «Кошка БУДЕТ есть рыбу.»  -> [('кошка','IS_ROLE','рыба')]
        САМЫЙ ДОРОГОЙ ДЕФЕКТ: в граф лёг перевёрнутый смысл «кошка является
        рыбой». Очередь его не называла — она говорила только о цели.
    «Кошка ДОЛЖНА есть мясо.» -> «есть» исчезал вовсе (только HAS_PROPERTY
        должный + OBJECT_OF мясо).
    Эталон: «Кошка будет ЛОВИТЬ рыбу.» -> CAN_DO ловить + OBJECT_OF рыба.

ПРИЧИНЫ ДВЕ, независимые:

  1. Словоформа «есть» в `STOP` (`core/morph.py`). ОЧЕРЕДЬ БЫЛА НЕПРАВА:
     она указывала `STOP/STOP_LEMMAS`, а в `STOP_LEMMAS` слова «есть» нет.
  2. `_purpose_part` отвергал часть цели: «есть ли своё сказуемое» искалось
     по ВСЕМ вариантам слова, а у «есть» помимо инфинитива (0.893) висит
     вариант «быть» VERB 3per pres весом 0.036 — шум словаря в ~25 раз тише.
     Тот же класс дефекта и тот же порог `NOISE_SCORE`, что в очереди Б
     («котором» и мусор-«котор» при 0.003).

ПОЧЕМУ НЕЛЬЗЯ ПРОСТО ВЫБРОСИТЬ «есть» ИЗ STOP (замер этого эксперимента —
мутация №3, 7 падений):

    «У кошки есть хвост.»   -> + ложный ('хвост','CAN_DO','есть')
    «Кошка есть животное.»  -> ('есть','OBJECT_OF','животное') ДЕГРАДАЦИЯ IS_ROLE
    «Кошка есть рыба.»      -> IS_ROLE ПОТЕРЯН                 ДЕГРАДАЦИЯ
    «У реки есть берега.»   -> [] вместо ('река','HAS_PART','берег')
    «Вода есть.»            -> ('вода','CAN_DO','есть') вместо []

Словарь связку и глагол НЕ РАЗЛИЧАЕТ (веса вариантов одного слова), решает
ОКРУЖЕНИЕ. `governs_infinitive()` в `core/morph.py`: «есть» становится
глаголом, только если перед ним союз цели (`чтобы/чтоб/дабы/затем/для/ради`),
модалка (`должен/надо` — ADJS/PRED) или личная форма глагола (VERB с лицом
или временем); частица между ними пропускается («чтобы НЕ есть»). Признак
берётся из граммем варианта, а не из списка слов — форм слишком много.

ЗАМЕРЕНО ПОСЛЕ:

    «Кошка спрятала мышь, чтобы не есть её.»
        + ('спрятать','PURPOSE','есть'), negated у цели, главное НЕ отрицано
    «Кошка спрятала мышь, чтобы есть её.»      -> та же связь без отрицания
    «Кошка будет есть рыбу.»  -> ('кошка','CAN_DO','есть') + ('есть','OBJECT_OF','рыба')
    «Кошка должна есть мясо.» -> CAN_DO есть + OBJECT_OF мясо (+ HAS_PROPERTY должный)
    связка и владение НЕ ИЗМЕНИЛИСЬ: IS_ROLE животное/рыба, HAS_PART хвост/берег,
    «Вода есть.» по-прежнему [].
