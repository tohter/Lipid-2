# Задача 31: СХЕМЫ КАК ДАННЫЕ (шаг 1 из п.29)

## Постановка (записана ДО правки — протокол проекта)

Проблема: путь вывода зашит в Python в двух местах.
  * `brain/simulator.py::why_stopped` — цепочка
    HAS_PART -> IS_A -> CAN_DO/OBJECT_OF зашита циклами.
  * `brain/social_sim.py::why_acted` — цепочка
    Violation -> IS_A(предательство) -> CAUSES* -> порог зашита кодом,
    порог `AGGRESSION_THRESHOLD=230` — числом в коде.

Пока путь в коде, учить модель нечему: некуда класть схему, и в C переносить
нечего (в C переедет интерпретатор, если путь станет данными).

## Решения (согласованы с хозяином)

1. **Где живут схемы**: секция `"schemes"` в файле мира, рядом с
   `entities` / `observations` / `transitions`. НЕ рёбра графа: шаги обхода не
   должны становиться кандидатами в причины при обходе.
2. **Два типа шагов**:
   * `edge` — «пройти по ребру relation из текущего узла в следующий»;
   * `threshold` — «проверить число (шкала агента) против порога».
3. **Пороги в схеме**: `230`, `8` (тики окна гнева) и подобные числа
   уезжают из кода в данные схемы. В коде остаётся только интерпретатор.

## Предложение (на согласование)

Схема = список шагов с РОЛЯМИ (переменными). Интерпретатор связывает роли с
узлами по мере обхода и в конце собирает ответ из привязанных значений.

```json
"schemes": {
  "process_stopped": {
    "question": "почему прекратился",
    "steps": [
      {"kind": "edge", "role": "parts", "from": "$subject",
       "relation": "HAS_PART", "fallback": "self"},
      {"kind": "edge", "role": "agents", "from": "$cause_subject",
       "relation": "IS_A", "mode": "transitive"},
      {"kind": "edge", "role": "verbs", "from": "$agents",
       "relation": "CAN_DO"},
      {"kind": "edge", "role": "targets", "from": "$verbs",
       "relation": "OBJECT_OF", "match": "$parts"}
    ],
    "answer": "потому что {agent} {verb:fin} {target}"
  }
}
```

## Критерий готовности

* Оба симулятора (fire и soc) дают ТЕ ЖЕ ответы, что и до правки:
  `почему прекратился пожар` -> «потому что вода гасит огонь»;
  `почему кошка съела канарейку` -> «потому что канарейка нарушила доверие...».
* Ответ собирается интерпретатором схемы, а не функцией `why_*`.
* В коде не остаётся ни одного порога/числа пластичности: все они в схеме.
* Замер: старый и новый вывод сравниваются ПОБУКВЕННО на обоих рассказах.
* Существующие 339 тестов остаются зелёными (или обновляются осознанно).
