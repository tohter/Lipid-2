# Задача 34: ОЖИДАНИЕ ИЗ ТЕКСТА (штрих A к задаче 32)

## СТАТУС: СДЕЛАНО (память — раздел [ЗАДАЧА 34])

## Постановка (ДО правки)

Сейчас ожидание («кошка ждёт, что канарейка НЕ расскажет») задаётся
ДИРЕКТИВОЙ `{"do":"expect",...}` в cat_canary_story.json — то есть рукой.
Рассказ же содержит фразу «Кошка попросила канарейку никому не
рассказывать тайну». Значит, ожидание можно ВЫВЕСТИ из текста.

## ЗАМЕР ДО ПРАВКИ (что уже даёт экстрактор)

СМ. ТАКЖЕ «ЧТО ПОКАЗАЛ ЗАМЕР ПОСЛЕ» НИЖЕ — он изменил решение.

  $ SimpleExtractor().extract("Кошка попросила канарейку никому не рассказывать тайну.")
  Events: EventRecord(subject='кошка', action='попросить', obj='канарейка',
                      tense='past', negated=True)
  Facts:  кошка --CAN_DO--> попросить
          попросить --OBJECT_OF--> канарейка
          рассказывать --OBJECT_OF--> тайна    <-- инфинитив-дополнение
  Токен «не» -> negated=True на событии.

ВЫВОД: все четыре ингредиента ожидания УЖЕ в тексте:
  holder = субъект просьбы (кошка),
  target = объект просьбы (канарейка),
  action = инфинитив-дополнение (рассказывать),
  negated = наличие «не».
Не хватает ПРАВИЛА, которое склеивает их в ожидание: конструкция
«X попросил Y <инфинитив>» = «X ожидает, что Y <инфинитив>» (+negated).

## Решение

Признать глаголы просьбы/запрета (просить, велеть, запретить,
умолять, приказать) маркером ОЖИДАНИЯ. Экстрактор порождает
ExpectationRecord (holder, target, action, negated, order, evidence) из
такой конструкции — рядом с событиями, тем же разбором.

## ЧТО ПОКАЗАЛ ЗАМЕР ПОСЛЕ (изменило решение)

1. Адресат просьбы бывает НЕ только в винительном: «попросил канарейку»
   (ВИН.), но «велел сыну» (ДАТ.). Фильтр только-ВИН на «Мать велела сыну
   вернуться домой» давал «просьба без адресата» — то есть терялись просьбы
   к людям, самый частый случай. Принимаем ВИН. и ДАТ.
2. Для «запретил разговаривать» отрицание содержится В ГЛАГОЛЕ, частицы
   «не» в предложении нет. Отрицание берётся из глагола (FORBID_VERBS).
3. ВИДОВОЙ РАЗРЫВ (главное). Инфинитив просьбы — несовершенный вид
   («рассказывать»), сказуемое рассказа — совершенный («рассказала» ->
   лемма «рассказать»). Леммы РАЗНЫЕ, direct сравнение не находит
   нарушение. pymorphy3 даёт граммему вида (perf/impf), но НЕ даёт пару
   вида. Эвристика по общей основе ЗАМЕРЕНА и отвергнута:
     рассказывать/рассказать -> «рассказ» (7)
     повторять/повторить     -> «повтор» (6)
     открывать/открыть       -> «откры» (5)
     нападать/напасть        -> «напа» (4)   неверно
     убивать/убить           -> «уби» (3)    неверно
     есть/съесть             -> «» (0)       неверно
   Граница проходит МЕЖДУ 4 и 5, поэтому VERB_STEM_MIN=5.
   СУДЬБА ЭВРИСТИКИ: она НЕ используется как единственный признак. Нарушение
   ищется по ОБЪЕКТУ («не рассказывать ТАЙНУ» / «рассказала ТАЙНУ»), а
   похожая основа глагола — ВТОРАЯ защита, без неё «не брать тайну» и
   «спрятала тайну» дали бы ложное нарушение. Отвергнутая пара уходит в
   ГРОМКОЕ предупреждение (stderr), а не в молчание.
4. ПОРЯДОК ИНИЦИАЛИЗАЦИИ. Ожидания из мира грузятся ДО сценария. ЗАМЕР:
   при загрузке ПОСЛЕ сценария born_tick = тик в его конце (10), а у
   события-нарушения order = 0; проверка born_tick <= ev.order давала ложь,
   и нарушение МОЛЧА не засчитывалось (нарушений: 0). Просьба звучит раньше
   своего нарушения — значит и рождаться ожидание должно раньше.

## Критерий готовности

  * Из «Кошка попросила канарейку не рассказывать тайну» выводится ожидание
    (holder=кошка, target=канарейка, action=рассказывать, negated=True).
  * Ожидание извлекается из ТЕКСТА, директива expect из story не нужна
    (или остаётся лишь как явный override — решить замером).
  * Ответ social_betrayal НЕ ухудшился (эталон задачи 31 держится).
  * Громкий отказ: просьба без инфинитива / без объекта — сказать, чего нет.
  * 374+ тестов зелёные, живая память чиста.
