# Задача 36 — витрина: обучила текст, спросила рассказ у симулятора

## Почему

Хозяин: «хочется, чтобы это было представлено наглядно… две вкладки:
обучение и симуляция. Пользователь может сам загрузить текст, а потом
задать вопрос симулятору».

ЗАМЕР, ПОКАЗЫВАЮЩИЙ ДЫРУ: в `ui/app_gui.py` упоминаний симулятора — **0**.
Вкладка «Симуляция» называется симуляцией, но симулятора не знает: внизу
стоит поле, которое зовёт `brain.process_input()`, то есть разбор слова по
памяти («что такое кошка»). Причину пожара спросить через окно НЕЛЬЗЯ —
даже когда `brain/question.py` умеет отвечать, а схемы выбираются из данных
(задача 35A). То есть механизм есть, витрины нет.

## Что считается сделанным

1. Загрузка рассказа в окно списком ФАЙЛОВ, а не списком имён в коде:
   пользователь видит, какие миры лежат на диске, выбирает, жмёт «Загрузить».
2. Симулятор для выбранного мира подбирается ПО ДАННЫМ МИРА (по handler из
   schemes), а не по имени рассказа. Третий рассказ не требует правки кода.
3. Вопрос из вкладки «Симуляция» уходит туда, куда выбрал пользователь:
   ядро (память слов) или симулятор (причина/следствие в рассказе). Переключатель
   видимый, состояние видно в строке статуса.
4. Отказ ГРОМКИЙ: рассказа нет / мир не выбран / схема не прошла / Учитель
   выключен — отдельная строка в чате с причиной. Молчаливого «не знаю» нет.
5. Обучение не трогается: вкладка «Обучение» как работала, так и работает,
   журнал и статусы те же.

## Чего СОЗНАТЕЛЬНО нет в этой задаче

  - прорисовки прохождения схемы кадрами (картинка «кошка -> гнев -> агрессия»);
  - выбора файла через диалог ОС (пока список найденных на диске);
  - записи загруженного рассказа в живую Вселенную (загрузка в симулятор —
    это чтение, обучение остаётся отдельной кнопкой).

## Проверка (чем ПРОВЕРЕНО, а не чем обещано)

Сквозная проверка — в `ui/headless.py` (гоняется живым окном под xvfb, см.
`tests/test_gui_live.py`), а не отдельным юнит-файлом. Проверяется весь путь,
которым пользуется человек: вкладка -> поле ввода именно этой вкладки ->
выбор рассказа из СПИСКА С ДИСКА -> загрузка -> вопрос -> ответ в чате, плюс
отказ словами на вопрос без загруженного рассказа.

ЗАМЕР ПОСЛЕ:
  headless: «✅ GUI: вкладки, ПКМ-копирование, журнал, обратный вопрос — ок»
  тесты:    408 OK (было 389)
  clean_world --check: rc=0, живая база после прогона пуста
  окно отвечает через вкладку: «потому что вода гасит огонь» и
  «потому что канарейка нарушил(а) доверие: кошка разозлил(а)сь, гнев
  перешёл в агрессию» — то есть ДВА разных класса симулятора, подобранных
  из данных мира, а не по имени файла.

ТРИ НАСТОЯЩИХ БАГА, НАЙДЕННЫХ ЭТОЙ ПРОВЕРКОЙ (не глазами):
  1. `_entry_return` был if/else по двум вкладкам — Enter на третьей вкладке
     угонял вопрос в ОБУЧЕНИЕ. Развилка сделана по активной вкладке.
  2. `_make_input` создаёт поле state="disabled", а включает его только
     `_attach_brain` — и только для learn/sim. Поле рассказа осталось серым
     навсегда. Включается сразу: рассказу ядро не нужно, и держать поле
     «до загрузки SDR» значило бы соврать про зависимости.
  3. Третья вкладка не была добавлена в `_set_buttons` — кнопка осталась бы
     активной во время чужой работы (двойной клик в тот же файл).

ЧЕГО СОЗНАТЕЛЬНО НЕТ: юнит-тестов на `brain/storyload.py` в отрыве от окна.
Его поведение проверяется тем же прогоном, что и окно; заводить второй
способ проверить то же самое — означало бы иметь два контракта, которые
могут разойтись.
