## 1. Что реально лежит в записи

```

base_entity  derived_entity
```

## 2. Пишут / читают / наследуют

| Поле | Что хранит | Пишут | Кто читает | Наслед. | Судьба |
|---|---|---|---|---|---|
| concept | лемма-канон | все каналы | всё (это ключ узла) | — | оставить |
| hierarchy | категории, [0]=ближайшая | учитель, wiki, текст | ответ, `_flatten_entity`; **в цепь предков не идёт** | — | свести с parent_concept |
| parent_concept | предок | только учитель | `_ancestor_chain` — единственная цепь | по цепи | виновник дыры с definition |
| definition | «чем является», одно предложение | учитель, wiki | ответ, **только если предка нет** | — | починить чтение |
| properties | признаки | учитель, wiki, текст | ответ + ядро (каждое = узел + HAS_PROPERTY) | **да** | только неизменное |
| delta_properties | отличие производного от родителя | учитель (пол обязателен, teachers/teacher1.py:479) | сваливается в properties при чтении | — | пол вывести в тип |
| actions | глаголы + [K,M,S] | учитель, текст | ответ, ядро | **да** | оставить |

## 3. Измеренные дыры этой таблицы

1. **aliases при поиске не читает никто.** Замер: запись «бегемот» c
   `aliases:["гиппопотам"]` -> запрос «гиппопотам» = НЕ НАЙДЕНО. То же с
   многочленными: «падшая женщина» найдена (и в косвенных падежах), её
   aliases «блудница», «шлюха» = НЕ НАЙДЕНО. Наблюдение SYNONYM_OF рядом
   тоже не помогает: мозг не вызывает `resolve_canonical_node` ни разу.
2. **definition теряется при наличии parent_concept.**
   `brain/lipid2_brain.py:468`: когда цепь есть, `base_entity` = родитель,
   а своё определение лежит в `derived_entity` и читается лишь при непустом
   `delta_properties`. Замер:
   - def без предка -> «Бык — самец крупного рогатого скота.»
   - def + предок + delta -> «Бык — это скот со свойствами: самец.»
   - def + предок + delta пусто/нет/hierarchy -> None -> повторный зов учителя
3. **relates_to вырыт и засыпан.** Слот есть в схеме ответа учителя
   (teachers/teacher1.py:425), в core/brain/lang его не читает ни один
   модуль — только упоминание в tests/test_teacher_relation_contract.py.
4. **Наследование только складывает.** Замер: сфинкс получил «пушистая»,
   мёртвая кошка получила «дышит». Механизма отмены нет.
5. **В ядро едет одно.** `brain/learner.py:1252` передаёт только properties,
   actions, hierarchy[0]. Каждое свойство становится PROPERTY-узлом и ребром
   HAS_PROPERTY — «свойство вместо синапса» синапс не отменяет.

## 4. Слияние двух каналов (определяет, можно ли заводить новое поле)

```
LISTS = hierarchy, properties, actions, delta_properties, aliases
        -> объединяет без повторов
прочие скаляры (definition, summary, parent_concept, learned_from, ...)
        -> побеждает ПЕРЫЙ НЕПУСТОЙ
provenance -> дополняет список
новое поле вне LISTS -> МОЛЧА затирается (замер: из двух ключей живёт один)
```

Следствие: любое новое поле обязано войти в `LISTS`, иначе знание учителя
теряется тихо. Форма связи — список пар, не словарь: `{rel: to}` теряет
второй объект того же типа (замер: «поршень часть двигателя» + «поршень
часть насоса» -> живёт один).

## 5. Зафиксированные решения (04.11, владелец)

| Вопрос | Решение |
|---|---|
| IS_A vs kind_of | одно и то же, переименование НЕ нужное, работает — и ладно |
| requires | поле сущности `{carrier: тип}`, не тип ребра, не запрет осиротевшего узла |
| изменяемое | в базу не пишется, живёт в симуляторе |
| properties | только неизменное (`sex` у кошки, не `пушистая`) |
| relates_to | `[{rel, to, via}]`, входит в LISTS, из него строятся рёбра |
| синонимы | одно поле `aliases`; SYNONYM_OF не наполнять (enum append-only) |
| омонимы | отложены до контекстного разрешения; числового id НЕТ, «главное значение» считать по частоте (support/weight), не по id |

## 6. Целевая запись

```jsonc
"бык": {
  "concept": "бык",
  "definition": "самец крупного рогатого скота",
  "sex": "male",                          // тип, не строка в properties
  "requires": {},
  "hierarchy": ["крупный рогатый скот", "млекопитающие", "животные"],
  "parent_concept": "скот",
  "properties": ["крупное"],              // ТОЛЬКО неизменное
  "actions": [{"name":"мычать","action_profile":[10,60,255]}],
  "aliases": ["буйвол-бык"],
  "relates_to": [{"rel":"PART_OF","to":"стадо","via":"часть"}]
}
```

```jsonc
"брат":    { "requires": {"carrier":"персона"} }  // всегда чей-то; «брат бывает старший» — законно без носителя
"озеро":   { "requires": {} }
"кошка":   { "sex":"female" }                     // кот и кошка — разные сущности
"балерина":{ "sex":"female" }  "балерун":{ "sex":"male" }
"падшая женщина": { "aliases": ["блудница","распутница","шлюха","потаскуха"] }
```

Морфология пол НЕ даёт (замер): род есть у всех слов (стол=m, жажда=f),
animacy различает живое/не живое. `балерун` = gender=n, `модель` = gender=f
при animacy=inan. Значит пол — именованный факт с закрытым значением.

## 7. Три имени-напоминания

```
properties = НЕИЗМЕННОЕ.  Сломается — перестанет быть этим? Нет -> сюда.
relates_to = СВЯЗЬ.        Есть вторая сущность -> сюда (парой, с via).
симулятор  = СОСТОЯНИЕ.    Сломается — станет другой? Да -> не в базу.
```

## 8. Открытое, что нужно решить владельцу

1. Золотой корпус благословляет свалку: из 84 кейсов `HAS_PROPERTY`
   требуется 6 раз, из них состояние/материал — 4
   (`Стол деревянный` = материал, `Гвозди ржавые` = состояние,
   `Хвост собаки мокрый` = состояние, `Кошки пушистые` = изменчивое).
   Правило «изменяемое не хранится» конфликтует с запертыми эталонами.
2. Прилагательное как замаскированный падеж. Замер одного имени — шести
   смыслов:
   ```
   мамина сумка    -> сумка HAS_PROPERTY мамин     (принадлежность)
   лисий хвост     -> хвост HAS_PROPERTY лисий     (это part_of)
   озёрный берег   -> берег HAS_PROPERTY озёрный   (часть)
   вчерашний дождь -> дождь HAS_PROPERTY вчерашний (время)
   золотое кольцо  -> кольцо HAS_PROPERTY золотой  (материал)
   зелёные глаза   -> глаз  HAS_PROPERTY зелёный   (и вот это — свойство)
   ```
3. Вид глагола: морфология aspect НЕ даёт, `ловить`/`поймать` — две леммы,
   не две формы одной.
4. Цельное выражение: `железная леди` -> «леди с железным свойством»,
   `битый час` -> ПУСТО. Признака «whole != sum» у нас нет.

## 9. Красный контракт, без которого нельзя ветвить свойства

Резолв `identity_path` ходит сквозь HAS_PROPERTY в обе стороны. Замер:

```
хвост  <-> лапа    ПУТЬ ЕСТЬ  [хвост-HAS_PROPERTY->мокрый <-HAS_PROPERTY-лапа]
трава  <-> попугай ПУТЬ ЕСТЬ  [трава-HAS_PROPERTY->зелёный <-HAS_PROPERTY-попугай]
```

Система объявляет хвост и лапу одним лицом. Поэтому «Property of Color»
разрешено строить только после контракта «общее свойство — не тождество».
Ложное ребро хуже отсутствующего.
