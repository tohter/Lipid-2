ЗАМЕР ПО ПУНКТУ БОССА: есть ли в ГРАФЕ место, где источник помещается БЕЗ
смены сигнатуры публичного метода, и сколько вызовов у integrate_knowledge.

Смысл вопроса: если вызовов много и поля нет — это миграция, её планировать
отдельно. Если вызовов мало и поле есть — это одна правка.

1) ПОЛЕ ДЛЯ ИСТОЧНИКА У РЕБРА ЕСТЬ (core/graph.py:94-103).
   Node.connect_to(..., source: str = "") и пишет:
       out_synapses_typed[target]["source"] = source      (только если непусто)
   То есть ребро графа УМЕЕТ носить источник. Носит молчание, потому что
   передавать ему нечего — см. пункт 2.

2) integrate_knowledge НЕ ПЕРЕДАЁТ источник, хотя сигнатуру менять НЕ ТРЕБУЕТСЯ.
   core/graph.py: def integrate_knowledge(self, knowledge: dict, weight=255).
   Первый аргумент — СВОБОДНЫЙ словарь: {"concept", "category", "properties",
   "actions"}. Источник может прийти ЭТИМ ЖЕ словарём (ключ "source") и уйти в
   connect_to. Сигнатура публичного метода при этом НЕ меняется, вызывающие не
   ломаются. Аргумент босса «смена сигнатуры ломает всех вызывающих» здесь не
   работает: ключей словаря у вызывающего столько, сколько он хочет.

3) СКОЛЬКО ВЫЗОВОВ (замер grep по всему дереву, тесты исключены):
       brain/learner.py:1253   self.core.integrate_knowledge({"concept": lemma, ...})
       core/graph.py:312       g.integrate_knowledge({...})   — внутренний самотест
   ОДИН внешний вызов. Не пять и не миграция.

4) ГДЕ ИМЕННО ТЕРЯЕТСЯ ИСТОЧНИК (единственная строка, которую надо починить):
   brain/learner.py:1253 передаёт словарь без "source", хотя в этой же функции
   источник ИЗВЕСТЕН (там же лежит learned_from=source). Данные есть, форма
   доставки есть, связь между ними не замкнута.

ВЫВОД: правка графа по П1 — ОДНА правка формы, без смены сигнатуры и без
миграции вызовов. Дыра не в отсутствии поля, а в незакрытой цепи
учитель -> learner -> integrate_knowledge -> connect_to.
