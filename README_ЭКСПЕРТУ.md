# Lipid-2 — что в этом архиве

Архив собран 26.10.2026. Это рабочая копия проекта, а не слепок «на показ»:
всё, что здесь описано, воспроизводится командой из этого каталога.

Не вошли (тяжёлое и не относящееся к делу): `.git/` (57 МБ), `.venv/` (1,4 ГБ),
`__pycache__/`, каталог `legacy/` (никем не импортируется), кэш эмбеддингов
`data/memory/sdr_words.bin` и `sdr_calibration.pkl` (проверено: программа
строит их заново сама, тесты в копии архива восстановили их за секунды),
эмбеддинговый пул `experiments/pool_emb*.npy` (30 МБ) и
`experiments/plasticity_sweep.json` (220 КБ, нигде не открывается — цифры из
него переписаны константами в тесте намеренно).

Живая память в архиве **обнулена намеренно**: `lipid_world.json` пуст, а
наработанный в старых прогонах `lipid_db.json` (17 слов: «флюгер», «джойстик»,
«экосистема») удалён, чтобы рецензент не принял мусор прогонов за знание.

Оставлен намеренно `experiments/ru_words.txt` (2 МБ): это не хлам, а сырой
корпус (108517 форм), по которому отобран порог шумных вариантов морфологии —
на него как на источник замера ссылается комментарий `core/morph.py:294`.
Файл открывают `tests/test_sdr_contract.py`, `experiments/config_eval.py` и
`experiments/scheme_eval.py`. Без него тесты НЕ падают, а скипаются — но тогда
исчезает возможность перепроверить порог, поэтому он в архиве.

## Запуск

    python -m pip install -r requirements.txt
    python run.py                  # графический интерфейс (Tkinter)
    LIPID2_STATUS=0 python -m unittest discover -s tests   # 628 тестов, ~2 мин

Тесты не требуют интернета и не требуют локальной модели. Живая модель
(локальный Gemma через HTTP на `localhost:8080`) нужна только учителю: без неё
канал LLM молчит, а извлечение из текста, память, сон и GUI работают.

## Идея в двух абзацах

Программа читает русские тексты, строит онтологический граф (сущности,
действия, отношения) и обучается в диалоге: непонятное слово порождает
любопытство, любопытство — вопрос, вопрос — запись ответа в память. Знание
приходит по четырём каналам: ответ пользователя, локальная LLM, Википедия,
извлечение из текста урока.

Ядро — не LLM. LLM здесь один из четырёх равноправных каналов, и её запись
проходит ту же проверку, что и пользовательская. Носитель знания — граф
отношений плюс мемристорноподобная таблица переходов, которая живёт по своей
арифметике: подтверждение укрепляет переход, сон его ослабляет, редкое гаснет.

## Карта каталогов

| Путь | Что там |

| `core/extract.py` | Экстрактор: предложение → список фактов `(голова, отношение, хвост)` + субъект/объект/действие/время. Не порождаются `ABOUT`, `SYNONYM_OF` и `IS_A` — последний приходит как `IS_ROLE` и переименовывается в `REL_ALIAS`, либо из иерархии учителя. |
| `core/storage.py` | Реестр отношений (`IS_A`, `CAN_DO`, `CAUSES`, `OBJECT_OF`, …) и формат хранилища. |
| `core/records.py` | Записи сущностей/событий/наблюдений, слияние записей из разных каналов, детерминированный порядок иерархии по происхождению. |
| `core/cortex.py`, `core/transitions.py` | Таблица переходов и её арифметика (подтверждение/затухание/порог). |

## Что сейчас умеет (проверено прогоном)

* `Кошка — млекопитающее.` → `кошка IS_A млекопитающее`
* `У кошки есть хвост.` → `кошка HAS_PART хвост`
* `Кошка ловит мышь.` → `кошка CAN_DO ловить`, `ловить OBJECT_OF мышь`
* `Огонь гасит вода.` → субъект не инвертируется, агент = вода
* `Хвост собаки мокрый.` → `хвост PART_OF собака` (а не «хвост — это собака»)
* `Кошка спрятала мышь, чтобы не есть её.` → `спрятать PURPOSE есть`
* `Дом, где жил пёс, сгорел.` → `жить LOCATED_IN дом`
* `Пожар погас вследствие дождя.` → `дождь CAUSES погаснуть` (причина — голова)
* `Витя дал кошке корм.` → `RECIPIENT`; `Кошка открыла мышь лапой.` → `INSTRUMENT`
* `Вода кипит при ста градусах.` → `CONDITION`; `Солнце светит днём.` → `CIRCUMSTANCE`
* Сон: консолидация после 80 тиков, затухание, редкий опыт умирает **и это
  называется именем в журнале и в панели GUI**, пробный сон не врал бы
  («умер бы», а не «умер»).
* Два разных состояния незнания: НЕ СПРАШИВАЛ и СПРОСИЛ-НО-ПУСТО; второе
  возвращается в очередь, первое не создаёт ложного «мы уже искали».

## Чего в программе нет — честно

1. **Долгой жизни не проверялось.** Живая память пуста. Сквозной цикл на
   сотнях уроков и десятках снов не прогонялся: растёт ли ядро, не выжигает ли
   затухание накопленное, — не измерено.
2. **`ABOUT` теряет предложение целиком.** `Он думает о погоде.` → пустой
   список фактов, без единой заметки о потере.
3. **`SYNONYM_OF` из текста не ложится в связи.** `Гиппопотам, или бегемот,
   живёт в реке.` даёт только `CAN_DO` и `LOCATED_IN`; тождества в мире нет,
   хотя отношение в реестре есть.
4. **Причинные придаточные не разбираются:** `потому что`, `так как`. Причина
   из такой фразы в граф не попадает.
5. **Отчёт молчит о промашках экстрактора:** заметки разбора (`sf.notes`) не
   доходят до пользовательского отчёта (`rep.notes`) — часть провалов
   невидима. Тот же класс молчания, что починен для сна.
6. **Двузначные предлоги `из-за` / `от` трактуются как место.** `Мальчик
   выглянул из-за угла` — верно; `Пожар гаснет из-за дождя` — ложь
   (`LOCATED_IN` вместо `CAUSES`). Морфология эти два случая не различает,
   поэтому выбор оставлен владельцу, а не решён «дефолтом по умолчанию».
7. **Локальный учитель слаб по факту, а не по промпту:** `hierarchy[0]`
   (ближайший род) совпадает с эталоном в 4 случаях из 11 (36 %). Правки
   промпта это не лечат — замерено.
8. **Редкий опыт не становится знанием.** При ровно одном подтверждении за сон
   сила перехода залипает на нуле и порог не берётся никогда. Это арифметика
   пары (затухание 5 %, сон раз в 80 тиков), а не поломка; цена редкости
   заперта тестом, но её стоит знать, глядя на результаты.
9. **Эмоции откалиброваны на глаз.** `attack` — не скорость роста (рост =
   `attack − decay`), потолок недостижим при ненулевом затухании (247 вместо
   255), а при `decay ≥ attack` эмоция не выражается ни при каком заряде — про
   это программа теперь кричит, но числа не пересчитаны: это решение владельца.

## Как устроены тесты

`tests/` — это контракты, а не юнит-тесты «на функцию». Каждый запертый факт
живёт в тексте предложения: тест подаёт фразу и требует конкретное отношение
между конкретными леммами. Отдельный класс тестов следит за тем, чтобы
программа не молчала о собственных провалах, и за тем, чтобы цифры в
документах совпадали с кодом (`test_header_table_is_measured_not_written` и
ему подобные). Есть тесты изоляции: тестовый прогон не имеет права тронуть
живую память.

Порядок чтения для рецензента: `memory.txt` (раздел «ОЧЕРЕДЬ»), затем
`experiments/SUBORDINATE_TASK.md`, затем `core/extract.py` и `brain/learner.py`.
