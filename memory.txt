[ОБЗОР ПРОЕКТА]
Цель: Автономный нейроморфный AI-движок Lipid-2 на базе разреженных бинарных векторов
(SDR-1024), предиктивного кортикального ядра (Predictive Cortex), нарративного
анализатора (Narrator) и гормональной саморегуляции (Homeostasis).

Принцип: Отказ от трансформеров в ЯДРЕ. Локальная LLM (llama.cpp @ 8080, Gemma 12B)
используется ТОЛЬКО как внешняя экспертная система ("Учитель") для первоначального
bootstrap неизвестных концептов и извлечения каузальных связей из текста.

ВАЖНО ПРО СМЫСЛ СЛОВА "ЯДРО": ядро не использует трансформеры для РАССУЖДЕНИЙ.
Оно использует одну small-эмбеддинг-модель как СЛОЙ КОДИРОВАНИЯ senses -> bits
(см. ниже, "семантический SDR"). Это не отступление от принципа, а его условие:
без семантики в битах предиктивный цикл оперирует шумом.

[ГЛАВНОЕ: SDR СТАЛ СЕМАНТИЧЕСКИМ] (2026-07, коммит b11f7b7)

Раньше SDR1024 строился буквенным хэшем (n-граммы букв -> 20 бит из 1024).
Замер показал, что сигнал ПЕРЕВЁРНУТ:
    кошка~кот        было  3/20   стало 16/20
    кошка~табуретка  было  4/20   стало  0/20
т.е. overlap несвязанных слов был ВЫШЕ, чем синонимов. На этом хэше были
построены ВСЕ пороги узнавания, bootstrap и "белые пятна" -- они были ложью.

Сейчас (core/encoder.py, EmbeddingEncoder):
  1. paraphrase-multilingual-MiniLM-L12-v2 (CPU, sentence-transformers) -> 384-float
  2. ВЫЧИТАНИЕ СРЕДНЕГО по калибровочному корпусу. ОБЯЗАТЕЛЬНО: у мультитязовых
     эмбеддингов крайняя анизотропия, "наивный" косинус любой пары 0.7..1.0,
     смысл тонет в общем направлении.
  3. top-k по 1024 случайным гиперплоскостям (RPP), k=20 -> ровно 20 активных бит.
     sign()-LSH не годится: даёт 512 активных бит и не разделяет пары.
  4. Детерминированно: фиксированный seed, калибровка закеширована в
     data/memory/sdr_calibration.pkl (23 МБ, regenerable, в .gitignore).

Инвариант НЕ изменён: 1024 бита, ровно 20 активных (~2%), публичный API SDR1024
те же самые (encode/overlap/to_bits). Всё, что потребляет SDR, менять не пришлось.

ЗАМЕРИРОВАННЫЕ СВОЙСТВА (полная таблица -- experiments/RESULTS.md):
  * Шумовой пол (overlap двух несвязанных слов) ~10 бит и НЕ РАСТЁТ с размером
    графа: 500 -> 15000 узлов, пол плоский. У буквенного хэша он рос лавинообразно.
  * Порог узнавания 13: ложных узнаваний 0.0% при 15 000 узлов, пропусков 25%.
    Асимметрия осознанна: ложное "узнал" = LLM не позван = тихая ложь без
    возможности исправления; пропуск = один лишний звонок LLM = дёшево.
  * Порог 20 битами не улучшить: при ON=20/32/48/64/96 нормированные FP/FN кривые
    совпадают. Ограничивает КАЧЕСТВО ЭМБЕДДИНГ-МОДЕЛИ, не число бит.

Пороги (core/cortex.py) -- ВСЕ пересчитаны по замерам, не по теории ортогональности:
    UNKNOWN_CEILING = 13   (ниже -> считаем концепт новым)
    KNOWN_FLOOR     = 17   (выше -> уверенно Known)
    HIT_THRESHOLD   = 13   (попадание предсказания)
    unknown_threshold() = clamp(шумовой_пол + 4, 13, 17)   -- АДАПТИВНО
  Шумовой пол измеряется САМИМ ГРАФОМ (SdrIndex.self_probe_floor(): узлы сравниваются
  между собой, сам узел исключается), а НЕ текущим входом. Пересчёт каждые 64 тика.
  Раньше пол зависел от того, с каким словом пришли, и фиксированная константа
  молча устаревала по мере роста графа.

ОПАСНАЯ ДЕГРАДАЦИЯ -- ТЕПЕРЬ ГРОМКАЯ (core/encoder.py:_warn_letterhash):
  В системном python3 нет numpy/torch -> get_encoder() откатывается на LetterHashEncoder,
  то есть приложение РАБОТАЕТ, но смысл не кодируется. Раньше это было ТИХО.
  Теперь: баннер в stderr + отдельная строка в чате GUI при старте.
  Запускать:  .venv/bin/python run.py     (LIPID2_SDR_BACKEND=letterhash -- только для тестов)

[УЗНАВАНИЕ ФОРМ СЛОВА] (core/lemma.py -- новый модуль, LemmaResolver)

"свойства флюгера" -> должен попасть в узел "флюгер". Делается на FLOAT-эмбеддингах
+ ключ по основанию слова, НЕ на битах SDR: на 20 битах морфология неразличима
(окна~окно = 7 бит, при этом щенок~собака = 13 бит -- диапазоны пересекаются).

  * COS_THRESHOLD = 0.85, ключ = первые 3 буквы нормализованного стема
    (ь/ъ/й отбрасываются). Замер: 22/24 формы, 1.0% ложных схлопываний на 8000 узлов.
    Полный стем проигрывает: чередования (огонь/огня) его ломают.
  * РЕЗОЛВЕР ТОЛЬКО ЧИТАЕТ: узлы не сливаются, ошибка обратима. Схлопывание на
    ЗАПИСИ было бы непоправимым.
  * GraphMemory.resolve() инициализирует резолвер лениво: иначе "забыл вызвать
    sync_lemmas()" превращался в тихое "система вдруг перестала понимать падежи".

[УСТРАНЁННЫЕ ТИХИЕ ПОТЕРИ ЗНАНИЙ] (это было главными багами проекта)

1. teachers/teacher1.py: write_json_file ПЕРЕЗАПИСЫВАЛ базовую сущность вырожденной
   производной -> иерархия, свойства и действия стирались. Теперь слияние:
   производная может ДОБАВИТЬ delta_properties/parent_concept, но НЕ может удалить
   base-иерархию/свойства/действия. Самоссылка parent_concept == concept отрезается.
2. teacher1: аргументы tool-call от локальной модели регулярно приходят битыми
   (обрезок по max_tokens, ```json-обёртка, хвостовая запятая). Раньше
   `json.loads() except: pass` оставлял СТРОКУ, `fn(**args)` падал с
   "argument after ** must be a mapping, not str", а внешний `except` РВАЛ весь
   цикл агента -> "Учитель ничего не сделал" без объяснения. Теперь: разбор с
   восстановлением (_parse_tool_args/_clip_json), а ошибка инструмента ВЕРНАТЬСЯ
   МОДЕЛИ в messages, чтобы она исправилась на следующем шаге, а не прерывать цикл.
3. brain: find_in_memory искал ПО ТОЧНОЙ СТРОКЕ. Каждый падеж = "новая сущность" ->
   повторный запрос к LLM за копией уже имеющегося знания.
4. brain: обработчики сверяли понятие с ФОРМОЙ ИЗ ЗАПРОСА -> "недостаточно данных"
   сразу после того, как данные были найдены. Теперь carriers matched_concept.
5. brain/ir.py: не знал родительного падежа ("свойства флюгера" = UNKNOWN), теперь
   5+ моделей вопроса + STOPWORDS. ПОРЯДОК ШАБЛОНОВ ВАЖЕН: движок возвращает первый
   матч, поэтому общий "какой X" обязан идти ПОСЛЕ "какие свойства у X", иначе
   проглатывает второе сущность.
6. brain/lipid2_brain.py: worker в GUI был без try/except -> любое исключение убивало
   поток, пользователь оставался с отправленным запросом и без ответа (выглядело
   как зависание). Теперь ошибка показывается в чате.
7. storage: в meta пишется sdr_encoder + config_hash (cfg=d39733936ebd). Би́ты SDR
   вне своего кодировщика бессмысленны, поэтому при несовпадении -- явное
   предупреждение, а не молчаливая подстановка.
8. Сохранение в data/memory/, а не в корень проекта.

[ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ -- НЕ ЗАМАЛЧИВАТЬ]

1. PredictiveCortex ОТКЛЮЧЁН от живого мозга: он используется только в legacy/,
   Lipid2Brain сам считает цикл. Решение не принято: либо подключить (тогда STDP,
   гормоны и предсказание участвуют), либо удалить. Пока это два параллельных мира.
   Работоспособность цикла проверена вручную: на замкнутой последовательности
   точность предсказания растёт до 88%, после первой холодной эпохи -- 0 промахов.
2. MiniLM-L12 слеп на часть синонимов: холостой~неженатый cos 0.47, быстрый~скорый
   0.46 -> overlap < 10, узнавание невозможно. Это СЛЕПАЯ ЗОНА МОДЕЛИ, бинаризатор
   её не починит. Лечение: LaBSE или ruBERT-тюнинг. Тесты используют только
   пары с cos >= 0.95 + проверку монотонности, а не "любые синонимы".
3. GUI (ui/app_gui.py) использует только process_input() и гормоны, API не задет;
   прямой работы с ядром/SDR из GUI нет.
4. Дорого стоят пропуски сведения: каждое пропущенное сведение формы = отдельный вызов LLM. Пачечного
   батча запросов к Учителю нет.

[ИНВАРИАНТЫ ДАННЫХ (онтология) -- НЕ ИЗМЕНЯЛИСЬ]

1. Иерархия (hierarchy): строго от частного к общему ([0] = кошачьи, [-1] = животные).
2. Пол: для гендерных узлов (кот, бык) первым элементом delta_properties обязан
   быть "самец".
3. Вектор действий [K, M, S] (0..255):
   K (Кинетика) -- физическое движение;
   M (Метаболизм) -- внутренние био-процессы (сон/дыхание = 180..255);
   S (Семиотика) -- сигналы, речь, эмоции.
4. SDR: 1024 бита, ровно 20 активных. Это инвариант АРХИТЕКТУРЫ, а не настройка.
