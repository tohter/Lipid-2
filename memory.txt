[ОБЗОР ПРОЕКТА]

Цель: автономный нейроморфный AI-движок Lipid-2 на разреженных бинарных
векторах (SDR-1024), предиктивном кортикальном ядре, графе знаний и
гормональной саморегуляции.

Принцип: ОТКАЗ ОТ ТРАНСФОРМЕРОВ в ядре для рассуждений. Локальная LLM —
внешний эксперт для bootstrap неизвестных концептов. Ядро использует ОДНУ
small-эмбеддинг-модель как СЛОЙ КОДИРОВАНИЯ senses -> bits.

ТЕКУЩИЙ БОЛЬШОЙ ЗАМЫСЕЛ (русский звуковой движок «понималка-говорилка»):
формировать из фактов БД грамматически верные русские предложения, чтобы в
итоге отказаться от трансформеров целиком. Архитектура: пользователь ->
ПОНИМАЛКА (роли+интент) -> МОЗГ (смысл/выбор по базе) -> ГОВОРИЛКА
(морфология+порядок) -> пользователь. БД — память между двумя языковыми
полюсами, не «корень». Первый кирпич (говорилка-конструктор) СДЕЛАН — см.
Текущее состояние. Думалка строится ПОСЛЕДНЕЙ (решение обоих советчиков).

[SDR СЕМАНТИЧЕСКИЙ] (core/encoder.py) — РЕШЕНО, НЕ ЧИНИТЬ

Раньше SDR1024 строился буквенным хэшем — сигнал был ПЕРЕВЁРНУТ, пороги на
нём лгали. Сейчас: paraphrase-multilingual-MiniLM-L12-v2 (CPU) -> 384 float;
вычитание среднего по калибровочному корпусу; top-k (k=20) по 1024 случайным
гиперплоскостям -> ровно 20 бит. Детерминированно (seed, калибровка
data/memory/sdr_calibration.pkl, regenerable, .gitignore). cfg-хэш
кодировщика d39733936ebd пишется в meta. ОПАСНАЯ ДЕГРАДАЦИЯ ГРОМКАЯ
(_warn_letterhash): нет numpy -> откат на LetterHashEncoder + баннер, т.к.
системный python3 без numpy молча лжёт.
Пороги (core/cortex.py): UNKNOWN_CEILING=13, KNOWN_FLOOR=17, HIT_THRESHOLD=13;
unknown_threshold() адаптивно измеряет шумовой пол САМОГО ГРАФА. Асимметрия
осознанна: ложное «узнал» = тихая ложь (хуже), пропуск = лишний звонок LLM.

[УЗНАВАНИЕ ФОРМ СЛОВА] (core/lemma.py, LemmaResolver): «свойства флюгера» ->
узел «флюгер». На FLOAT-эмбеддингах (на 20 битах морфология неразличима).
COS_THRESHOLD=0.85. Резолвер ТОЛЬКО ЧИТАЕТ (узлы не сливаются).

[ВИРТУАЛЬНОЕ ОКРУЖЕНИЕ]: .venv (1.4 ГБ) с numpy, scipy, sentence-transformers,
torch 2.14.1+cpu, pymorphy3 + dicts-ru. torch НЕ грузится при импорте
core.storage. core/records.py — чистый stdlib (правило формата лёгким каналам).

[КОМПИЛИРУЕМОЕ ЯДРО (C/C++)] — итоговую программу планируется писать на
компилируемом языке (хозяин — ассемблерщик/PLC). Пороги (13/17, шумовой пол)
от языка НЕ зависят. Компилируемо по природе: SDR (16 слов uint64), граф в
битах, предиктивный цикл, STDP, гормоны. Ресурсоёмки НЕ ядро: MiniLM 449 МБ,
pymorphy3+dicts 46 МБ, sdr_calibration 47 МБ. ГРАНИЦА: OFFLINE-фабрикация
(Python, обучение/извлечение/морфология/калибровка) -> компактный бинарный
образ; ОНЛАЙН-ядро (C, SDR/граф/цикл/гормоны) без Python. В ESP32 (520 КБ) да,
в Arduino Uno (2 КБ) НЕТ. «1-2 мкс/узел на ESP32» — НЕ замер, а прикидка.
ПРАВИЛА ПОД C (уже действуют): формат данных = контракт; имя узла — текстом;
пороги из образа с cfg-хэшем; никаких torch/numpy в онлайн-части; ключевые
алгоритмы — с поштучной проверкой на целых.

  * ЗАМЕР ПЕРЕД ПРАВКОЙ по производственному пути; замок пишется КРАСНЫМ ДО
    правки; тест проверяет ПРОЦЕСС, а не состояние после перезапуска.
  * Замер обязан проходить сквозь НАСТОЯЩИЙ конвейер, а не напрямую (урок 93):
    ручная вставка — в разбор, прогон — через learn_from_text.
  * Мера, которая не может двинуться, проверяется ДО того, как стать
    критерием (91); мера, которая льстит, опаснее отсутствия меры.
  * Мутация, прошедшая зелёной, лечится ЗАМЕРОМ ДОСТИЖИМОСТИ, а не новым
    тестом по догадке (84); guard без фразы, где без него РАЗНЫЙ исход, —
    декорация, его удалять, а не запирать (10.4, M9).
  * «Нет X» доказывается перебором дорожки данных от источника до приёмника,
    а не отсутствием слова в сигнатуре (78).
  * Краснота контракта меряется в ЧИСТОЙ выгрузке коммита, падения — по
    классам, каждый со своей причиной (88).
  * Отказ надо отличать от пустоты и платить двумя вещами сразу (83);
    «молчать» для владения проверено, а не предложено (103).
  * Рукописные числа/указатели протухают молча — сверять КОМАНДОЙ (95).
  * Сочинённое число, внесённое в закон без замка, остаётся сочинённым (95).
  * Пробник обязан показать известное до того, как ему верить (54).
  * Справочный указатель в очереди сверять командой, а не глазами.
  * После вставки в большой файл проверять границы метода деревом AST, а не
    глазами (хвост из 1613 строк стал мёртвым кодом, поймал старый контракт).
  * git checkout -- файла ОТКАТЫВАЕТ ВСЕ правки к HEAD; восстанавливать из
    /tmp-бэкапа по sha256, читать git status после КАЖДОГО шага с checkout.

Уроки про самих советчиков: пустой узел DOM хуже отсутствующего (100); «появился
ответ» = новый id, а не «узлов больше» (101); id появляется раньше конца
стриминга — ждать стабильную длину (102); главная страница сервиса — рулетка,
держать полный адрес диалога (104).

Уроки про лексику/морфологию (для звукового движка): одно отношение получает
три имени в зависимости от конструкции (жена OBJECT_OF сын / жена PART_OF сын —
дыра 100); одушевлённость лжёт («семья» грамматически неодушевлена, 101);
словарь ролевых слов покрывает лучше, но первую цифру себе ПОДГАНИТА — у
рассуждающих моделей не подхватывать reasoning_content вместо content (102);
не всякое отношение годится для обхода (cousin RELATIONAL_TO сын — формально
найдено, семантически бессмысленно, 104).

Симптом: connect_to к той же цели ПЕРЕЗАПИСЫВАЛ первое ребро (out_synapses_typed был Dict[str, dict] по имени цели). Пока ядро только складывало связи, потерю не было видно; перед чтением для рассуждений надо чинить (в Lipid1 было списком). Решение (минимально-инвазивное):
- Новый модуль core/synapses.py (ОТДЕЛЬНО от core/graph.py: storage обязан видеть тип, а импорт storage->graph создал бы цикл). Класс SynapseList(list): каждое ребро {"target","rel_type","weight"[,"source"]}. Обратная совместимость чтения: __getitem__[цель] -> ПЕРВОЕ ребро к цели; [индекс] -> по позиции; .get()/.items() как у dict (первое ребро на цель); .raw_edges() -> ВСЕ рёбра (для сериализации и рассуждений); .all_for(цель) -> все к цели.

- core/storage.py save_json: итерирует raw_edges(), а НЕ .items() (иначе второе ребро снова теряется на диске); есть legacy-ветка для dict-формы. selfcheck DummyNode пишет через SynapseList.append.
- graph.py print_node_associations / resolve_canonical_node оставлены на .items() (первое ребро на цель) — пригодно для демо-печати и SYNONYM_OF.

  животное» — OBJECT_OF животное. HAS_PROPERTY/IS_A приходят структурированно

РЕШЕНИЕ ПО HAS_PART vs PART_OF (Виктор, глобально): ОСТАВИТЬ ОБА, не отказываться.
- HAS_PART = «X имеет часть Y» (слева направо): «у кошки есть хвост», «птица HAS_PART крыло»,
  «самолёт HAS_PART крыло» (сходство птицы и самолёта — оба имеют крылья).
- PART_OF = «Y является частью X» (справа налево): «хвост PART_OF кошка».
- Они ВЗАИМОДОПОЛНЯЮТ, не конфликтуют; в одних примерах «имеет часть», в других «является частью».
- НО в конструкции «у X Y» без «есть» используем ТОЛЬКО PART_OF (справа налево), НЕ HAS_PART.
